PHASE 中文 Wiki

PHASE 是一款 Unity 像素平台遊戲。每次成功跳躍，世界就換一種顏色；只有符合目前顏色的石材、尖刺與雷射會存在或致命。

機制與編關說明已整合七色水晶、多平台與 Prefab；原有八關圖片拍攝於 e4332a2，水晶關卡圖片來自本次整合版。公開預覽是否同步需另外驗證。

世界與 Wick

美術方向定名為「月夜的染色採石場」：低亮度夜空、固定的月亮與星點、遠山與採石場殘柱，前景是以 8×8 格拼接的錯縫石材。永久存在的石材是骨白與灰色；只在特定相位存在的石材染成紅、藍、綠或混色。

主角 Wick 是披著骨白斗篷的旅人，暗色臉孔、深色靴子。角色身上的顏色都有遊戲意義：

  • 眼睛＝目前相位色（紅、藍、綠）。
  • 兜帽與圍巾＝衝刺是否可用。琥珀色、圍巾 5 格長表示還有一次衝刺；暗橘色、圍巾縮成 3 格並下垂表示已用掉。
  • 整頂兜帽＝空中的耐力。耐力低於 55 時逐漸染紅並以 1 像素抖動，越低抖得越快；20 以下最紅並輕微明暗脈動。落地立即恢復；斗篷保持骨白，眼睛仍顯示相位，圍巾獨立顯示衝刺存量。

角色狀態示意：由遊戲正式的 PhasePixels renderer 繪製（24×28 原生像素，放大 4 倍），不是遊玩截圖。

故事、Wick 的身世與旅程目的尚未定稿。遊戲內以幾何、顏色和動作呈現規則，不放教學文字。

選單、選關與改鍵

網頁版先點一下遊戲畫面取得鍵盤焦點；網頁本身沒有按鈕。選單與全螢幕都在遊戲畫面內，原生版與網頁版相同。

  • 標題四個圖示：開始第 1 關、選關、遊戲內編輯器、設定（齒輪）。左右（方向鍵或移動鍵）選擇，跳躍或 Enter 確認，也可點擊。
  • 關卡中按 Esc 暫停：繼續、選關、設定、回標題。再按 Esc 繼續；關閉選單後先放開所有按鍵，遊戲才會繼續。
  • 選關每格是該房間的縮圖與關卡數字，選中的格子是藍框；版面依畫面比例排列並放大到填滿大部分畫面。十五關隨時都能選；從暫停開啟時游標停在目前關卡。完成最後一關的勝利橫幅下有「重玩第 1 關」與「選關」兩個圖示。
  • 設定畫面每個動作有兩個獨立鍵位格。方向鍵移動、Enter、跳躍或點擊讓格子閃爍並綁定下一個按鍵，Esc 取消、Backspace 清除；下方的循環箭頭還原全部預設。這些導覽鍵不受改鍵影響。
  • 再下一列是全螢幕開關：開啟時旋鈕在右、軌道點亮，Enter、跳躍或點擊切換。itch.io 遊戲框的全螢幕按鈕也可用。最下方的 X 關閉設定，也可按 Esc。
  • Shift 是一個邏輯鍵，同時接受左右 Shift。可綁定字母、數字、方向鍵、Space、Shift、Enter 與常用標點。重複的按鍵、無法顯示的按鍵，或讓動作沒有任何鍵的變更，會以紅框閃爍並保留原設定。
  • 設定立即套用、跨房間保留，存在這台裝置（Unity PlayerPrefs phase.keys.v1；網頁版存在瀏覽器的網站資料）。舊網頁設定視窗的鍵位不會轉移。

動作與相位

控制器以原生像素、Y 向下、每秒 60 步運算。Wick 的碰撞框是 8×11 像素，蹲下時 8×6。以下數值取自 PhaseController.cs。

相位循環

紅→藍→綠→紅

正式十一關每次進房都從紅開始（原始沙盒換房時保留相位）。只有成功起跳會換色，包括地面跳、牆跳、攀爬跳、圓水晶補跳與衝刺中的跳躍。衝刺、攀爬、落地、走路都不換色，這是保留顏色的主要手段。

跳躍

  • 普通跳躍可從地面、離地 0.1 秒內，或貼著牆（3 像素內）起跳；吃到圓水晶後，另可使用一次空中補跳。
  • 按住跳躍鍵約可上升 28 原生像素（3.5 格），輕點只會跳起少許。這是依程式數值推算的近似值。
  • 落地前 0.08 秒內按下跳躍會被記住，著地即起跳（需仍按著）。

貼牆、牆跳與攀爬

  • 滑牆：空中朝牆按住方向（或只按住抓牆），下落速度從很慢開始，在 1.2 秒內逐漸回到正常。
  • 牆跳：貼牆沒在抓牆時按跳，會往牆的反方向彈出。
  • 攀爬：貼牆按住抓牆鍵即可抓住（耐力需至少 20，且不在上升中）。按上以每秒 45 像素往上、按下以每秒 80 像素往下；爬到牆頂會自動翻上去。
  • 攀爬跳：抓牆時按跳會直直往上跳；若在 0.2 秒內再按離牆方向，就轉成往外的牆跳並退回耗掉的耐力。
耐力（上限 110，落地立刻補滿）
狀態消耗
往上爬約每秒 45.5
掛著不動每秒 10

耐力歸零會自動放手。耗盡後仍按住抓牆貼著牆，下滑速度上限是每秒 45 像素；放開、離牆或按下就恢復正常落速。

衝刺

  • 共有 1 次，用掉後要落地才補回。衝刺有 0.2 秒冷卻。
  • 方向是八方向，取當下的方向鍵；沒按方向就朝面向。地面上往斜下衝刺會變成蹲低滑行。
  • 衝刺會讓房間的移動平台出發（見移動平台）。
  • 衝刺不是無敵：尖刺和雷射在衝刺路徑上的每一個像素都會檢查。
  • 衝刺途中貼牆或在地面上按跳，會接成一次跳躍，也會換色。

死亡與檢查點

碰到目前相位有效的尖刺或雷射、掉出畫面下緣、或被平台與機構擠進牆裡／推過封閉的房間邊界，都會死亡；開放的出口邊界則照常換房。約 0.28 秒後在本房間的起點重生：顏色回到紅、衝刺與耐力補滿，移動平台與齒輪回到初始位置。經過時間、跳躍、衝刺與死亡次數則保留。

重生前的最後 0.12 秒，八顆淺色像素會向出生點聚攏；沒有全畫面閃白。重落地（向下速度至少 120 像素／秒）則揚起六顆白色塵粒。

十一關中，走出房間右緣就進入下一關，並以 0.18 秒的水平像素滑動轉場；每個新房間都是新的檢查點。各房間左緣封閉，第 8 關接水晶關卡，第 11 關右緣封閉。

物件圖鑑

相位地形與七種 mask

每塊地形、尖刺與雷射都有一個 phaseMask（1–7），由紅＝1、藍＝2、綠＝4 相加而成。目前相位包含在 mask 裡時，石材是實體、尖刺與雷射是致命的。

失效的石材只剩淡色底與虛線邊；雙色石材用兩個顏色嵌點標出有效相位。地形另有舊欄位 phase：phaseMask 為 0 時，phase = −1 等於白（7），0／1／2 等於紅／藍／綠。

例：房間 6 的青色平台在藍與綠時可站。從它起跳的那一刻你變紅，它也同時消失，所以下一個落點必須是含紅的石材。

重疊時延後實體化

換色時，如果一塊剛變成實體的石材正和 Wick、移動平台或齒輪零件重疊，它會先保持可穿過，畫成較亮的實線框；等重疊的東西離開後才變成實體。原本就是實體的雙色石材在換色時不受影響。延後中的石材也擋不住雷射。

例：紅色時站在藍色虛線平台的範圍內起跳，變藍後那塊平台不會把你卡住，等你離開它才出現。

七色水晶

顏色符合目前相位才能拾取；白色全相位可用，雙色水晶接受其中任一相位。錯色時呈半透明，拾取本身不換色。

形狀效果
圓形儲存一次空中補跳，最多一跳；重新按跳躍才使用，成功跳出時才換色。
方形直接恢復一次衝刺，即使原本已滿也會消耗水晶；不改相位，也不取消正在進行的衝刺。

實際落地或重生後水晶恢復，落地也會清除未用的補跳。圓水晶存量用斗篷上的白色環表示；眼睛、兜帽與圍巾仍保留原來的相位與衝刺意義。雷射先判定致命，不能靠同時拾取水晶免死。

衝刺驅動的移動平台

白灰色的鉚釘平台，所有相位都存在。它只在你衝刺的瞬間出發，與你人在哪裡無關。站在上面或攀在它側面會被載著走；被它推進牆裡、推過封閉的房間邊界或推進危險物會死亡。它也會擋住雷射。同一場景可放多個平台；每次有效衝刺會同時啟動所有平台，各自依自己的路線移動。

returns 關閉：站點循環
每衝刺一次，平台前往下一個站點，每段 0.3 秒；連續衝刺會排隊依序執行。到最後一站後，下一次衝刺直接回到第一站。只有兩站時就是來回切換。
returns 開啟：去了會回來
只能有兩個站點，且必須水平或垂直排列。平台本體可維持橫向，只讓路線上下移動。衝刺後平台衝向第二站，停 0.2 秒，再慢慢回到第一站。從端點走完全程時，去程 0.2 秒、回程 1.2 秒；回程中途再衝刺會從目前位置重新出發，時間依剩餘距離等比縮短。

例：房間 6 的渡船有三站（x＝96、152、208）。第一次衝刺停在中站；第二次到右站；第三次直接回到 96。

攀爬連動齒輪

一面白色攀爬牆和一塊白色橫平台由齒輪與齒條連動（貼地橋四顆、架高橋三顆）。只有真正爬動造成的位移會驅動它：往上爬，牆跟著往上並帶著你，平台同步向右滑；往下爬則反向。掛著不動、放手、滑落、衝刺，或往上爬卻被擋住時，都不會轉動。

  • 牆和平台的行程相同（八關都是 24 像素），到端點就停。
  • 任一零件撞到實體（例如目前相位存在的石材或移動平台）就停在那一格；所以顏色會決定機構能不能動。
  • 站在平台上會被帶著走；牆與平台都會擋雷射。齒輪與齒條只是裝飾，沒有碰撞。
  • 死亡重生時回到初始位置。

例：房間 7 的平台路徑上有一個紅色 8×8 方塊。紅色時攀爬，平台一出發就撞上；先跳一次變藍，方塊消失，平台才能滑滿 24 像素。

相位尖刺

尖刺有上、下、左、右四個方向，長度以 8 像素為一格。它不是實體，站不上去；只有齒根那條 3 像素寬的帶狀區域會致命，而且只在 mask 包含目前相位時有效。失效時保留暗色齒形，雙色尖刺只在第一格標記顏色。碰撞檢查涵蓋整段移動路徑，包括衝刺、換色瞬間與被平台載運。

例：房間 5 地上有一排綠色朝上尖刺。保持藍色衝刺過去是安全的；如果在上面跳一下變綠，尖刺立刻生效。

常亮雷射

8×8 發射器朝一個方向射出 4 像素寬的光束，沒有計時、不閃爍。光束停在第一個目前存在的實體（石材、移動平台、齒輪牆或平台）或房間邊緣。

  • 白色雷射在所有相位都致命；其他顏色照 mask 規則。
  • 失效的光束以低透明度保留，仍看得見位置；致命時有暗色外框與亮芯。
  • 失效（虛線）石材、延後實體化中的石材都擋不住光束。
  • 發射器本身只是美術，沒有碰撞。

例：房間 3 的白色雷射從下往上直射。貼地橋往右滑到它上方後，光束被橋面截斷；橋面以外的區域仍須避開。

十一個房間

前八關是 PhaseDemo1–PhaseDemo8，由 DemoRooms.json 產生。前三關各介紹一個核心：跳躍換色、衝刺驅動平台、攀爬驅動齒輪；後五關把它們和尖刺、雷射、混色平台組合起來。解法預設折疊，下方是測試裡重播的參考路線，不代表唯一解。

1換色階梯

每次跳躍後，哪一塊平台會存在？

藍／綠／紅單色平台・青色雷射（向下）

看解法
  1. 從地面跳上藍色平台：起跳讓你變藍，藍平台出現。
  2. 再跳上綠色平台（變綠），再跳上紅色平台（變紅）。
  3. 走到白色出口。青色雷射是藍＋綠，紅色時無害。

2低頂渡船

渡船該在什麼時候開？

兩站循環移動平台・低垂石頂・紅色雷射（向下）

看解法
  1. 先跳上停在左站的渡船。這一跳讓你變藍，紅色雷射失效。
  2. 站穩後衝刺，渡船把你載到右站。
  3. 走上右側石地。若先衝刺再上船，渡船會自己開走；再衝刺一次它才會開回來。

3齒輪抬門

封住的通道要怎麼打開？

攀爬連動齒輪・白色雷射（向上，所有相位致命）

看解法
  1. 抓住白牆往上爬，讓牆升 24 像素、貼地橋同步右滑 24 像素；上方石頂擋住翻越，牆底才是打開的通道。
  2. 放手落回牆下，從抬起的閘門底部向右衝刺上橋，走到邊緣。
  3. 起跳（變藍）後再向右衝刺，落在出口平台。

4五連跳

能不能事先讀出整段色序？

五塊單色平台・綠色雷射（向上）

看解法
  1. 五塊平台依序是藍、綠、紅、藍、綠，剛好是連跳五次的顏色。
  2. 站在紅平台上時，紅平台擋住下方綠光；從紅平台起跳變藍後才越過光束，綠光此時無害。
  3. 第五跳變綠，落在綠平台，再走上出口。

5保色穿刺

什麼時候「再跳一次」反而是錯的？

藍色平台・綠色尖刺・黃色雷射（紅＋綠，向上）

看解法
  1. 跳上第一塊藍平台，你變成藍色。
  2. 不要再跳。用衝刺保持藍色，越過綠色尖刺與黃色雷射，落在第二塊藍平台。
  3. 如果在這裡再跳一次會變綠：尖刺與雷射同時生效，兩塊藍平台也會消失。

6三站轉乘

再衝刺一次有用，還是會開過頭？

三站循環渡船・青色與黃色平台・紅色尖刺・青色雷射（向上）

看解法
  1. 跳上渡船（變藍），衝刺一次，讓渡船停在中站。
  2. 跳上青色平台（變綠；青＝藍＋綠，仍存在）。
  3. 再跳上黃色平台（變紅；黃＝紅＋綠）。此時穿過青色光束，紅色時它無害。
  4. 多衝刺會讓渡船開往右站，再下一次直接回左站，可以重來。

7相位卡齒

連動機構為什麼卡住了？

攀爬連動齒輪・紅色阻擋塊・藍色尖刺・洋紅色雷射（紅＋藍，向上）・綠色出口

看解法
  1. 攀爬前先原地跳一次，變藍。紅色方塊消失，平台才能滑滿。
  2. 爬牆把閘門抬滿，再放手落回牆下；從門底向右衝刺上貼地橋，走到邊緣。
  3. 起跳變綠：藍色尖刺與洋紅雷射失效，綠色出口出現。接著向右衝刺登上出口。

8色序預算

哪些動作應該保留顏色？

齒輪・三站渡船・藍色尖刺・藍色雷射・洋紅色低台・黃色出口

看解法
  1. 原地跳一次變藍，再爬牆把平台推滿。
  2. 放手落回牆下，從門底向右衝刺上貼地橋；這次衝刺同時把渡船從 x＝208 叫到較近的 x＝176 站。
  3. 跳上渡船，變綠。
  4. 衝刺：渡船把你往右載，綠色時藍尖刺與藍雷射都無害。
  5. 向上衝刺，登上黃色出口（紅＋綠，綠色時存在）。

藍色時，洋紅色低台可以接住失手的你。

關卡編輯

先試編一張圖可用遊戲內編輯器。需要移動平台或齒輪時，用 Unity 格線繪圖與 Inspector；正式八關則改 DemoRooms.json 再重建。

遊戲內編輯器：畫圖、試玩與保存

  1. 開啟遊戲，在標題畫面按右兩次選鉛筆，再按跳躍或 Enter（也可直接點鉛筆）。
  2. 固定面板裡有工具：地板、四向尖刺、四向雷射、跳躍水晶（圓）、衝刺水晶（方）、出生點與橡皮擦，以及七種顏色：永久白、紅、藍、綠、黃、洋紅、青。一格是 8×8 原生像素。
  3. 滑鼠左鍵繪製、右鍵擦除；也可用方向鍵移動游標，跳躍鍵繪製、抓牆鍵擦除、衝刺鍵切換工具、1–7 選顏色。工具列固定在地圖右側（視窗較高時在下方），不會遮住地圖。
  4. 出生時是紅色，Wick 不能與紅色有效的地形、尖刺或紅色雷射光束重疊。按面板上的播放圖示或 Enter 試玩；地圖無效時畫面閃紅框，不會開始。試玩中按 Esc 回到原本草稿，再按 Esc 回標題。
  5. 面板上的上箭頭匯入、下箭頭匯出 JSON。網頁版會下載 phase-custom-map.json 或開啟檔案選擇器，也就是網頁版的匯出 JSON／匯入 JSON；在 Unity Editor 中則使用剪貼簿。

草稿只存在目前裝置（Unity PlayerPrefs phase.editor.v1；網頁版存在瀏覽器的網站資料），沒有雲端同步。換裝置或清除網站資料前先匯出。試玩不會改寫 Unity 場景或正式關卡。

目前可編靜態地形、四向尖刺、四向雷射、跳躍／衝刺水晶與出生點，範圍 40×22 格（320×176 像素）。移動平台、齒輪與房間串接需使用 Unity。

自訂地圖 JSON

匯入的是單張地圖，有下列五個頂層欄位，另可加選用的 lasers 與 crystals；不是 {"rooms": […]}，也不能直接貼入 Demo 房間的 goal、route 或機構欄位。下例可直接匯入：

{
  "name": "第一張地圖",
  "blocks": [
    {"x": 0, "y": 168, "w": 320, "h": 8, "phase": -1, "phaseMask": 7},
    {"x": 80, "y": 144, "w": 32, "h": 8, "phase": -1, "phaseMask": 2}
  ],
  "spikes": [{"x": 144, "y": 160, "length": 8, "direction": 0, "phaseMask": 4}],
  "spawnX": 24,
  "spawnY": 152
}

座標與寬高／尖刺長度皆為 8 的倍數、在 320×176 內，物件不可占同一格。地形用 phase: -1 並以 phaseMask 指定七色；尖刺方向 0 上、1 下、2 左、3 右。雷射每格一個：{"x", "y", "direction", "phaseMask"}，方向同尖刺；水晶每格一個：{"x", "y", "kind", "phaseMask"}，kind 0 跳躍、1 衝刺。沒有雷射或水晶時，匯出檔省略這兩個欄位。至少一格地形，出生點 x＝0–312、y＝0–160 且對齊 8；名稱至多 64 字元，JSON 至多 200,000 字元。

Unity：用格線畫地形

  1. 先另存一個房間，保持編輯模式。
  2. 選單 PHASE › Paint Grid terrain 開啟「PHASE Grid」，勾選「畫地磚」，在「顏色」選七種相位色之一。
  3. 在 Scene View 以滑鼠左鍵點或拖曳，每次畫一格 8×8 石材；已占用的地形格會略過，支援 Undo。
  4. 關閉「畫地磚」後，使用一般選取、Inspector 與 Delete 調整。要畫大石台，修改 PhaseTerrain.size 的像素寬高。
  5. 尖刺、雷射、移動平台與齒輪使用下列元件；儲存場景再 Play。Play 中不能繪圖。

原生 BoxCollider2D 提供模型矩形並同步相位和機構移動；Wick 的接觸仍由固定步進控制器計算，Unity 物理引擎不推動角色。

座標與格線

  • 單位是原生像素。房間至少 320×180，原點在左上，Y 向下。
  • 放在 Transform 上的位置用 Unity Y ＝ −原生 Y：原生 (80, 144) 要填 Position (80, −144)。Transform 是物件左上角，透過 Unity Grid 對齊最近的 8 像素格。
  • Inspector 欄位裡的座標（出生點、平台站點、齒輪平台與行程）直接填原生 Y，不加負號。
  • 地形寬高取最近的 8 倍數（最小 8）。Inspector 仍填像素：7 格長的石台填 56，不是 7；站點與機構端點也要對齊格線，移動途中則逐像素前進。
  • Wick 高 11 像素，所以要站在 y＝160 的地面上，出生點 Y 填 149。
  • 視窗較寬時，房間右側與碰到右緣的地形會延伸；較高時，遊戲區上下置中並補上石頂與虛空漸暗。八關原生 y＝0–8 也有實體石頂。左右擴展會延長邊界地形的碰撞；上下補景則不新增落腳處。

每個房間是一個掛著 PhaseSandbox、PhaseGrid 與 Unity Grid 的根物件（cellSize＝8, 8, 1；無間隔、無旋轉、縮放為 1），其餘元件放在它的子物件上；啟動時從子物件收集。

用 Prefab 放置機關

從 PHASE/Add 新增，或把 Assets/Phase/Prefabs/ 的平台、齒輪、雷射、尖刺與圓／方水晶拖到 PHASE Grid 下。地磚繼續用 Grid painter。

移動或複製整個 Prefab 根物件，路線會一起移動。選 Platform／Mechanism 子物件調整參數；各實例可獨立覆寫。保持旋轉 0、縮放 1，使用 8 像素移動吸附。根物件 (80, −144) 配節點 (0, 0)→(0, −64)，就是向上移動 64 像素的橫平台。

圓／方水晶使用 PhaseCrystal：kind 選 Jump／Dash、phaseMask 選 1–7，Transform 為 8×8 拾取格左上角。

建立時會檢查兩件事，不符就丟出例外：

  • 行程相等：platformEndX − platformStart.x 必須等於牆的行程。因此往上爬時平台一定往右移。
  • 齒輪咬合：輸出齒輪位於 x＝牆 x＋牆寬＋39，必須介於 platformEndX + 6 與 platformStart.x + platformSize.x − 6 之間，也就是平台在兩端位置都蓋住齒輪且各留 6 像素。

既有八關可用 Prefab 根物件 Unity 座標 (72, −104)、牆子物件 (0, 0)、8×56、wallTop −24；platformStart (16, 56)、56×8、platformEndX 40。行程 24，轉成世界座標後齒輪仍在 x＝119。

手工做一個房間

  1. 在 Editor 開啟既有房間（例如 PhaseDemo1.unity），用 File › Save As 另存新檔，例如 Assets/Scenes/MyRoom.unity。不要用 PhaseDemo1–8 的檔名，重建八關會覆寫它們。
  2. 保留根物件 PHASE 上的 PhaseSandbox、PhaseGrid 與 Grid，以及它指向的 pixelCamera（場景中的 Camera）與 pixelMaterial（PixelSurface.mat）。
  3. 在 PHASE 底下修改、複製或刪除子物件。Transform 位置填 (x, −y)；平台站點、齒輪平台與 wallTop 填原生 Y。
  4. 調整 spawn。獨立試玩時清空 leftScene 與 rightScene，兩側就會封閉；從 PhaseDemo1 另存的場景原本會連到 PhaseDemo2。
  5. 儲存場景，再按 Play。

DemoRooms.json

檔案是 {"rooms": [ … ]}，必須剛好 8 個房間。所有座標都是原生像素、Y 向下，不加負號。方向用數字：0 上、1 下、2 左、3 右。

每個房間的欄位
欄位內容
name房間名稱。
spawnX, spawnY出生點。
blocks石材 {x, y, w, h, phase, phaseMask}。phase 請寫明（−1 為白）；phaseMask 省略時為 0。
spikes{x, y, length, direction, phaseMask}。length 是像素，必須是 8 的倍數（Inspector 是格數）。
crystals{x, y, kind, phaseMask}，kind 0＝圓形補跳、1＝方形補衝刺。

route, goal只給測試用：route 是逐段輸入（frames、x、y、jump、dash、grab），goal 是終點的 x、落腳 y、顏色、跳躍與衝刺次數與機構升高量。

重建八關

重建會從零覆寫 Assets/Scenes/PhaseDemo1–8.unity。在這八個場景裡用 Inspector 做的手工修改都會消失。重建前先儲存開啟中的場景，並用 Git commit 或複製檔案備份。PhaseDemo1.1、沙盒與齒輪 Demo 不受影響。

透過常駐的 Unity GUI Editor 與 Pipeline 執行，不使用 -batchmode。在專案根目錄：

unity status --project-path "$PWD" --until-ready --json
unity command --project-path "$PWD" run_script -- --file Verification/BackgroundEditor.cs --entry BackgroundEditor.Run
unity command --project-path "$PWD" eval 'PhaseSandboxBuilder.CreateDemoRooms();'

Builder 會依序建立八個場景、讓第 N 關的 rightScene 指向第 N＋1 關、全部勾選 checkpointOnEntry，並補入 Build Settings，保留其他場景；第 8 關會連到 PhaseCrystal1。水晶三關另用 PhaseSandboxBuilder.CreateCrystalRooms() 重建，會覆寫這三個生成場景。

驗證

重建後跑關卡測試：每個房間的 route 都要零死亡抵達 goal。

unity command --project-path "$PWD" run_tests -- --mode editor --filter DemoRoomTests --async_tests true
unity command --project-path "$PWD" test_status

重複 test_status 直到狀態是 completed 並檢查摘要。若改了 C# 原始碼，先執行 recompile -- --focus false 並等 recompile_status 成功。實際遊玩、鍵盤輸入與截圖檢查見 Demo.md 與 Development.md。

網頁版是另一個步驟

Unity 場景更新不會自動更新網頁預覽。本機建置與瀏覽器檢查：

python3 Verification/BuildWeb.py
node Verification/DemoWebSmoke.cjs Builds/Web

發布到公開網址需要另外上傳，或由擁有者先完成 runner 與 Pages 設定後交給 CI，見 Web.md。

新增更多關卡

目前的 builder 不是任意數量的關卡編輯器。它目前分成固定八關 PhaseDemo1–8 與三關 PhaseCrystal1–3；第 8 關接水晶三關，最後一關右緣封閉。新增房間需要另外修改並驗證：

  • PhaseSandboxBuilder.CreateDemoRooms() 的房間數量檢查與連結；
  • 新場景與 Build Settings；
  • BuildWeb.py 的場景清單與 DemoWebSmoke.cjs 的路線；
  • DemoRoomTests 的房間數與測試案例。

只想試做的話，可以像 PhaseDemo1.1 一樣另開場景、手工擺元件，不經過 builder。
